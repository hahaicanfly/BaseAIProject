# Plan First Rule

## 原則

**執行任何非瑣碎任務前，必須先進入 Plan Mode，撰寫計劃供用戶審查。**

## 適用情境

以下情境必須先寫計劃：
- 新功能實作
- 架構變更
- 大規模重構
- 影響多個檔案的修改
- 涉及安全或成本的決策
- 刪除或移動檔案

## 例外情境

以下可直接執行：
- 單一檔案的小修改（< 20 行）
- 格式調整
- 註解更新
- 明確的 bug 修復（已定位問題）
- 用戶明確指示「直接執行」

## 計劃內容

```markdown
## 執行計劃：[任務名稱]

### 目標
[要達成什麼]

### 影響範圍
- 檔案：[列表]
- 模組：[列表]

### 執行步驟
1. [步驟 1]
2. [步驟 2]
3. [步驟 3]

### 風險評估
- [潛在風險及緩解措施]

### 驗證方式
- [如何確認完成]
```

## 工作流程

1. 分析任務需求
2. 進入 Plan Mode
3. 撰寫執行計劃
4. **等待用戶確認**
5. 用戶同意後才開始實作
6. 按計劃執行
7. 完成後報告結果

## 為什麼重要

- 確保開發方向符合用戶預期
- 避免大量無效工作
- 提供審查和修正的機會
- 建立可追溯的決策記錄
