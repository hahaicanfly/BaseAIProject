# Cost Optimization Rules

## 模型選用

| 任務複雜度 | 模型 | 範例 |
|-----------|------|------|
| 簡單 | `haiku` | 格式化、簡單查詢、快速驗證 |
| 中等 | `sonnet` | 代碼生成、一般分析、日常任務 |
| 複雜 | `opus` | 架構設計、複雜推理、核心決策 |

## 選用原則

### 預設使用 sonnet
大多數開發任務使用 sonnet 即可勝任。

### 升級到 opus 的時機
- 系統架構設計
- 複雜的技術決策
- 需要深度分析的問題
- 涉及多模組的重構

### 降級到 haiku 的時機
- 簡單的是/否判斷
- 固定模板填充
- 格式轉換
- 快速驗證

## API 成本控制

### 快取策略
- 相同請求不重複調用
- 結果本地快取
- 設定合理的快取過期時間

### 輸入優化
- 圖片壓縮/降解析度
- 精簡 prompt
- 避免不必要的 context

### 批次處理
- 合併多個小請求
- 減少 API 呼叫次數

## 邊緣 AI 優先

能在設備本地完成的任務，不要發 API：
- OCR 文字辨識
- 語言偵測
- 基礎文字處理
- 圖片預處理
- 格式驗證

## 監控提醒

如果發現以下情況，主動提醒用戶：
- 大量重複的 API 請求
- 可以本地化的任務使用雲端 API
- 高成本操作沒有快取
- 使用過高等級模型處理簡單任務

## 成本意識檢查清單

在設計功能時考慮：
- [ ] 這個操作需要 API 嗎？能本地完成嗎？
- [ ] 選用的模型等級適當嗎？
- [ ] 有快取機制嗎？
- [ ] 輸入資料有優化嗎？
- [ ] 失敗重試有限制嗎？
