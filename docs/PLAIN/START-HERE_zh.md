# 從這裡開始 — 無術語版

> 寫給非技術背景的使用者。這頁講的內容和[主 README](../../README_zh.md) 完全一樣，只是不用術語講。
> 如果這頁跟規則檔說的不一樣，以規則檔為準。

## 這東西到底是什麼

你要請一個 AI 幫你做軟體。放著不管的話，AI 會很有自信地做錯事、忘記昨天學到的教訓、然後在還沒做完的時候跟你說做完了。

這個專案就是攔住那些狀況的規則和安全網。你不需要讀那些規則，也不用背任何東西 —— 讀規則的是 AI，而且其中一部分是由電腦強制執行的，不是靠自律。

## 開始之前

你只需要兩樣東西：

1. **裝好 Claude Code**，而且在終端機裡能用。
2. **一份這個專案的副本**，當作你要工作的資料夾。

就這樣。你不需要懂 git、不需要懂 Python、也不需要知道 hook 是什麼。

## 第一句話該打什麼

在專案資料夾裡打開 Claude Code，把這句貼進去：

```
幫我完成專案初始化，交給它做前兩步
```

它會問你一兩個關於「你要做什麼」的問題，然後自己把設定做完。**如果哪個問題你看不懂，直接說看不懂** —— 「我不知道那是什麼意思」是完全合格的回答，它會換個說法重問，不會硬推著你往下走。

設定完之後，直接用平常講話的方式描述你想做的東西就行。不用記任何特殊指令。

如果你比較希望被一題一題帶著走，就打 `/guided-start`，然後描述你的目標。終點一樣，過程更多引導。

## 你提出需求之後會發生什麼

依序三件事：

1. **它先判斷這件事有多大。** 小而明確的（改錯字、改一行）它直接做。比這大的，它會先寫一份計畫給你看，等你點頭才動工 —— 不會先動手再跟你報告。
2. **它開始做**，需要的時候把工作拆給不同的專職角色。
3. **檢查的人不能是動手的人。** 寫程式的那一方，沒有資格宣告自己寫的東西是對的。這個分離是刻意設計的 —— 這套機制能抓到自己的錯，主要就靠這一條。

## 怎麼知道它真的做完了

每一段工作結束都是同樣三行：

```
✓ 完成：[具體做了什麼]
→ 下一步：[接下來要做什麼]
⚠ 注意：[你該擔心的事]
```

重點在於**每一行都指得出一個你打得開的檔案**。「測試通過」只是一個說法；「測試通過，輸出在 `state/acceptance/...`」才是證據。想把證據翻成白話，直接說：「**翻成白話給我看**」。

## 出問題的時候

用你自己的話描述你看到什麼就好，把紅色的錯誤訊息整段貼上來也完全可以。你不需要自己診斷任何東西。

它被設計成寧可停下來，也不要用猜的：

- **有兩種合理解讀時會停下來問你**，需要做難以回復的動作之前也會先問。
- **卡住的時候會明講。** 失敗到一定次數它會停，把試過什麼講給你聽，然後問你 —— 而不是安靜地用你的預算再試第四次。

## 它絕對不會擅自做的事

這幾條是**電腦擋的**，不是靠 AI 自律，它講不贏也繞不過：

- 直接提交到你的主分支
- 對主分支強制推送或強制重置
- 讀你的機密檔案 —— 密碼、API 金鑰、`.env`
- 把網路上抓來的東西直接灌進你的終端機執行
- 刪掉指派範圍以外的檔案

## 你會看到的幾個詞，一行說完

| 詞 | 意思 |
|---|---|
| **ExecPlan** | 大改動的正式計畫書。你同意了才會動工。 |
| **Plan Mode** | 同樣的概念，用在規模小一點的工作 —— 計畫直接寫在對話裡，等你點頭。 |
| **Agent** | AI 把一部分工作分出去交給的專職角色。 |
| **Skill** | 針對重複性工作存起來的固定做法。 |
| **Hook** | 自動執行的檢查，不管有沒有人記得都會跑。 |
| **Invariant** | 絕不妥協的硬規則，而且真的有 hook 在擋。 |
| **驗收 (Acceptance)** | 做完的證明 —— 是實際跑出來的結果，不是一句「應該沒問題」。 |
| **交接 (Handoff)** | 一段工作留給下一段的紙條，讓事情不會在換 session 時掉在地上。 |
| **Tier pack** | 依照當下跑的是哪個 AI 模型，給它份量剛好的規則本。你完全不用碰。 |

## 老實說的部分

這套機制能讓 AI 在「**把事情做對**」這件事上可靠很多，但它沒辦法告訴你「**你要的是不是對的東西**」。品味、產品判斷、使用者會不會買單 —— 這些還是你的事。AI 碰到這類問題時，規則要求它把選項攤給你選，而不是自己拍板然後講得很有把握。
