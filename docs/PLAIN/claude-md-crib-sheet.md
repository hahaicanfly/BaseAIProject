# CLAUDE.md 決策樹對照卡(一頁版)

> 只解釋路由判斷裡最卡關的那幾個詞。這張表原本放在 CLAUDE.md,F-003 之後搬到了每個 session 注入的 tier pack(`.claude/tiers/` 下的 `strong.md` / `mid.md` / `light.md`)的「Before acting」段落;如有出入,以該檔原文為準。

- **核心一句話**:小改動、單一檔案、已經知道怎麼修 → 直接做;牽涉多個檔案或大改動 → 先寫一份計畫給你看過、你同意了才動工。這份計畫如果影響多個模組或 API,就叫 **ExecPlan**;規模較小、其餘非小事的任務,就叫 **Plan Mode**。兩者核心都是「先給你看過再做」,差別只在規模與正式度。
- **第 0 項(先問清楚)**:使用者是誰、成功標準、範圍邊界、觸發時機這 4 項缺 2 項以上 → 先在對話裡問清楚,不用猜的就開始寫計畫。
- **第 1 項(ExecPlan)**:跨模組、跨 API、大規模重構 → 存成正式計畫檔(`docs/plans/active/`,規格見 `docs/plans/PLANS.md`),等你同意才動工。
- **第 2 項(Plan Mode)**:其他非小事(新功能、改多個檔案、刪檔) → 用 Plan Mode 當場寫一份計畫給你看,你同意後才執行。
- **第 3 項(直接做)**:單一檔案 <20 行的改動、已經定位原因的 bug 修正、純格式調整 → 不用等計畫,直接做。
- **第 4 項**:驗收標準沒辦法機械判斷(品味/商業判斷) → 提供幾個方案讓你選,不會自己拍板。
